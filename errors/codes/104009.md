---
code: 104009
identifier: message_decode_failed
title: Message decode failed
summary: An AI Transport codec threw while decoding a message that arrived on the channel. The message is still delivered with no decoded event, and decoding carries on with the messages after it.
---

## What you should do

Inspect the `cause` for what threw. If it came from a codec of your own, fix it so that it decodes the message, or returns nothing for a message it does not handle, rather than throwing. Nothing needs reconnecting: only that one message failed, and your application still receives it raw, so it can decide what to show in its place.

In the Vercel chat transport, a message that arrives live during a reply and cannot be decoded ends that reply with this error. One read from history is skipped, and the reply goes on without it.

## Why it happens

Each message carrying the codec's name and id is decoded by that codec. This error is raised when the codec throws, with the thrown value preserved as the `cause`. The usual reason is that the agent and the client are using different versions of a codec, or a custom codec is meeting a payload shape it does not handle.

## What you'll see

The error is reported with code 104009 and status 500, to the decoder's error handler rather than from a call you made. The message takes the form `unable to process channel message; ...`.
