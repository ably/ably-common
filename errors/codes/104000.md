code: 104000
identifier: streamed_message_finalize_failed
title: Streamed message could not be finalized
summary: A streamed message could not be completed on the channel because an append was not published. The SDK then tried to repair the message by re-sending the accumulated content in a single update, but that also failed.
---

## What you should do

The partial message stays on the channel, and the write that raised this error has stopped. Keep retrying by publishing an update to the partial message with its complete content.

If retries keep failing, inspect the error's `cause` to find the underlying problem.

## Why it happens

A streamed message starts with a publish, followed by a series of appends. The SDK sends appends without waiting for each one to be acknowledged. It only detects a failed append when the stream ends or its writes are flushed.

The SDK then tries to repair the message by re-sending its full accumulated content in a single update. This error means that the repair also failed. The original failure is preserved as the error's cause.

## What you'll see

Clients on the channel see the partial message. It does not include the content of the appends that failed.

The error is reported with code 104000 and status 500. The message takes the form `unable to repair stream; ...`. An event writer reports it from `flush()` and `close()`, and from the next write after it. A pipe reports it as the `cause` of a pipe error (code 104008).
