identifier: pipe_failed
title: Pipe failed
summary: An AI Transport pipe stopped before the end of its source. The source threw, an event could not be encoded, the channel refused a write, or a streamed message could not be repaired.
---

## What you should do

Inspect the `cause` for which of these happened; it carries its own error code. If the source threw, the model or provider failed, so produce the reply again: under a durable-execution framework such as Temporal, the engine retries the failed step for you; otherwise start the reply again from your application, which in a chat client is a regenerate. If the cause is from the channel or the codec, fix that before you try again, since a retry will fail the same way.

The partial reply already on the channel stays there. The pipe ends no stream it had open.

## Why it happens

A pipe reads events from a source, such as a model's stream, and writes each one to the channel as it arrives. It stops at the first failure: the source throws, the codec cannot encode an event, the channel refuses a publish or update, or the repair of a streamed message whose append failed also fails. Before it stops, the pipe flushes and repairs what it has written. The originating error is preserved as the `cause`.

## What you'll see

The error is reported with code 104008 and status 500. Messages take the form `unable to pipe; source failed: ...`, `unable to pipe; encode failed for event ...`, `unable to pipe; write failed for event ...`, or `unable to pipe; repair failed: ...`.
