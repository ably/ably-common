title: Connectivity check failed
summary: The SDK could not reach its internet connectivity check endpoint, so it treated the network as unavailable and did not try Ably's fallback endpoints. It is reported as the cause of a disconnection.
---

## What you should do

Usually nothing. The SDK keeps retrying, and the connection is re-established once the network is available again.

If it keeps happening while the device otherwise has internet access, check that the network and any firewall or proxy between the client and Ably allow requests to the connectivity check endpoint. If your network cannot reach it, set the `connectivityCheckUrl` client option to an endpoint you host that returns a successful response.

## Why it happens

When the SDK cannot reach Ably's primary endpoint, or a WebSocket connection is slow to open, it sends a request to a connectivity check endpoint to find out whether the device has internet access at all. If that request fails, the SDK assumes there is no network, so it stops trying fallback endpoints and moves the connection to the disconnected state.

The usual cause is a genuine loss of network, such as a device going offline or switching networks. It can also happen when a firewall or proxy blocks the connectivity check endpoint but allows other traffic.

## What you'll see

The connection moves to the disconnected state with Ably error code 80003 and the message `Unable to connect (network unreachable)`. That error's `cause` carries code 80025 with the message `Connectivity check failed` and HTTP status 404.
