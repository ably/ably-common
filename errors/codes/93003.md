title: Annotation summary entry limit reached
summary: An annotation was rejected because the message's annotation summary already held the maximum number of distinct combinations of annotation type, name and client ID. Annotations that would not add a new combination are still accepted.
---

## What you should do

If messages in your app legitimately need summaries with more entries, contact https://ably.com/support to enquire about raising the limit for your account. Nothing needs to change for annotations that update or remove an existing entry, such as a client deleting its reaction, which are always accepted.

## Why it happens

A message's [annotation summary](https://ably.com/docs/messages/annotations) records each distinct combination of annotation type, name and client ID, and is sent with every copy of the message, so its size is limited. Once the summary holds the maximum number of entries (1000 by default), an annotation that would add a new combination is refused. Existing clients can still remove their reactions. This means that the size of the annotation summary (sent with every subsequent version of that message) is bounded.

Note that applications should not assume that the limit is enforced strictly - in particular, a burst of annotations sent at the same time may well all be accepted even if that takes the number of annotations above the limit - but at some point, once the limit has been exceeded for that message, new annotations will start to be rejected.

## What you'll see

The error is reported with code 93003 and HTTP status 400. The message is of the form `Unable to add annotation: the summary for message <serial> has reached the maximum of 1000 distinct (type, name, clientId) entries`.
